# SFT V3-30 真实 Rollout 离线奖励回放

## 目的

合成正负例通过奖励测试，并不代表奖励在模型真实输出上有效。本阶段让 SFT V3-30
实际回答全部 90 条 RL prompts，再用双数据库奖励评分，不更新任何模型参数。

## 结果

| 指标 | 结果 |
| --- | ---: |
| Rollout 数 | 90 |
| 安全率 | 100.0% |
| 两套数据库均可执行 | 98.9% |
| 两套数据库结果均正确 | 64/90（71.1%） |
| 重复原错误 SQL | 6/90（6.7%） |
| 两套数据库判定不一致 | 3 |
| 平均奖励 | 1.05 |

与原始错误 SQL 相比，84 条奖励改善、6 条持平、0 条变差。奖励值包含
`-0.4/-0.2/0.0/1.5` 四档，标准差 0.71，不是所有输出得到相同分数，因此能够为
候选排序提供非退化学习信号。

## 分类表现

| 错误类型 | 正确/总数 | 正确率 |
| --- | ---: | ---: |
| aggregation | 9/12 | 75.0% |
| date | 10/15 | 66.7% |
| duplicate_counting | 0/7 | 0.0% |
| filter | 15/17 | 88.2% |
| join_type | 8/15 | 53.3% |
| schema_linking | 12/13 | 92.3% |
| syntax_error | 10/11 | 90.9% |

重复计数是最明确的短板：7 条全部失败。JOIN 和日期也仍有稳定错误，适合下一轮重点
构造偏好数据；语法和 Schema 已较强，不应继续高比例训练，避免遗忘。

## 双数据库验证的实际价值

回放中有 3 条候选在一套数据库上匹配、另一套不匹配。如果只使用单个小数据库，这些
错误 SQL 会得到满分并成为错误的强化信号。双数据库判定因此不仅是理论防护，而是在
模型真实输出中实际触发了。

## Hard Preference 数据

64 条正确 rollout 不再重复训练。其余 26 条真实失败被转换为：

```text
同一 Prompt + 参考正确 SQL（chosen）+ 模型真实错误 SQL（rejected）
```

分布为：重复计数 7、JOIN 7、日期 5、聚合 3、过滤 2、Schema 1、语法 1。所有偏好
对的正确答案奖励都高于错误答案，最小间隔为 1.50。

## 阶段结论

- 奖励层：通过。安全、可执行、结果正确和重复行为均能被区分。
- GRPO 训练：暂不启动。SFT V3 的最终留出集仍有一个回退案例。
- 下一步：先使用 26 条真实 hard preference pairs 做小规模偏好优化或定向 SFT，验证
  能否消除重复计数与 JOIN 错误且不损害强项；通过后再正式运行 GRPO。

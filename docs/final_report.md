# SQL Debug Agent 最终实验报告

## 结论

项目完整跑通了“基线评测 → 数据构建 → SFT → Bad Case 分析 → RL 数据与奖励设计
→ GRPO → 冻结集对比验证”。在同一模型、提示词、数据库和确定性生成配置下：

| 模型 | 正确数 | 正确率 | 相对上一阶段 |
| --- | ---: | ---: | ---: |
| Qwen2.5-Coder-1.5B Base | 16/28 | 57.1% | — |
| 60 步 QLoRA SFT | 23/28 | 82.1% | +25.0 pp |
| SFT + 40 步 GRPO | **25/28** | **89.3%** | **+7.1 pp** |

GRPO 相对 SFT 修复 2 个 Schema Linking 任务，没有造成任何任务回退。因此当前最佳
版本是 SFT + GRPO。

## 问题与 Agent 链路

目标不是把自然语言直接转成 SQL，而是修复已有的错误 SQL：

```text
用户问题 + Schema + 错误 SQL
        ↓
只读安全检查与 SQLite 执行
        ↓
执行错误或结果差异反馈
        ↓
模型生成修正 SQL
        ↓
双数据库执行结果验证
```

这个设定适合金融分析场景：SQL 即使能够执行，也可能因为 JOIN、日期边界、重复计数
或过滤条件错误而产生错误报表。

## 数据构建

项目没有直接下载公开数据集。先分析真实模型基线的短板，再从业务问题倒推训练数据：

- 构造正确的金融分析 SQL。
- 按语法、Schema Linking、聚合、重复计数、JOIN、过滤、日期七类注入单一错误。
- 用 SQLite 验证参考 SQL 可执行，且错误 SQL 与参考结果不同。
- 按错误模板分组切分，防止同模板同时出现在训练集和验证集。
- 最终得到 218 条 SFT 训练数据、42 条内部验证数据。

最终 28 条测试题在训练前冻结；其 SHA256 为：

```text
51d8caad2e12d1e6e11ab2b8febf05f6e0ef8466b025e32dbd6cc3c4dd454c67
```

## 为什么先做 SFT

初始模型在 JOIN、日期和过滤错误上表现较弱。此时问题主要是模型尚未稳定掌握
“最小修改 SQL”的基本行为，因此先用 SFT 学习标准纠错轨迹：

```text
问题 + Schema + 错误 SQL + 执行反馈 → 正确 SQL
```

早期 SFT V2 曾出现训练损失下降、冻结测试正确率反而下降的负结果。这促使项目加入：

- 新冻结测试集；
- 按任务正确率选 checkpoint，而不是只看 token loss；
- 回退任务检查；
- SQLite 执行等价评测修复；
- 强项回放和多模板数据。

云端标准 PEFT SFT 最终在冻结测试集达到 23/28，比同环境 Base 多修复 7 题。

## 为什么需要 GRPO

SFT 后仍有可执行但语义错误的 SQL，且普通 corrective replay 无法利用
chosen/rejected 之间的相对质量。项目因此从真实模型 rollout 中提取 26 条失败难例，
并设计可自动验证的 GRPO 奖励。

奖励同时在两套同 Schema、不同数据的 SQLite 数据库上执行：

```text
安全且可执行                         +0.2
两套数据库结果均与参考一致           +1.0
成功修复原始错误                     +0.3
重复提交原错误 SQL                   -0.2
危险 SQL                             -1.0
终局仍失败                           -0.2
```

双数据库验证用于减少“错误 SQL 在一套小数据上碰巧得到相同结果”的奖励作弊。

## GRPO 优化过程

第一版每题只采样 2 个候选，5 步中所有候选奖励相同，`reward_std=0`，实际没有学习
信号。因此没有盲目继续跑长训练，而是做了三项优化：

1. 只训练 26 条真实 rollout 失败难例；
2. 每题候选数从 2 增加到 4；
3. 采样温度从 0.8 提高到 1.2，并自动审计奖励方差。

40 步正式训练中有 3 步出现组内奖励差异，产生非零优势和梯度。虽然学习信号稀疏，
冻结测试集仍从 23/28 提升到 25/28。

## 评测协议

- 基座：`Qwen/Qwen2.5-Coder-1.5B-Instruct`
- SFT：4-bit QLoRA，60 步
- GRPO：26 条 hard prompts，4 generations，temperature 1.2，40 步
- 最终集：28 条训练前冻结任务，每类 4 条
- 推理：单次修复、`do_sample=False`
- 指标：两套数据库 execution-match accuracy
- 三个模型使用相同提示词、最大输出长度和批大小

## 局限与下一步

- 最终测试集只有 28 条，置信区间较宽。
- 数据库 Schema 只有客户、账户、交易三张表，不能代表复杂企业数据仓库。
- GRPO 只有 3/40 步产生奖励方差，后续应增加更难且更多样的真实失败样本。
- 当前指标验证执行结果，不包含 SQL 可读性、查询成本和人工业务审查。
- 不应再使用这 28 条测试题选择训练超参数；后续迭代需要新建第三套冻结测试集。

这些限制不影响本次结论：在预先冻结、未参与训练的测试集上，SFT 和 GRPO 都带来了
可测量提升，且最终 GRPO 没有引入回退。
